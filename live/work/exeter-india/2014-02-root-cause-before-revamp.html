A clean-up plan from one reopened defect

A portal defect kept getting reopened. I took the developer's root-cause analysis, found the same dead, repeated and tangled code across several portal controllers and proposed a three-phase clean-up to the delivery head.

3

phases proposed

remove dead code, modularize, extract shared modules

Without it
The team kept patching the same defect each time it reopened, while the same patterns sat in other controllers.
The call
Fix the root cause in phases, starting in slack time, without putting the release at risk.
What I did
Proposed the phases: remove dead code, modularize the controllers, then pull shared logic into one module. I asked the delivery head when phase one could start.
What changed
The fix went into the next hotfix, and the project manager backed the plan: redesign and refactoring both had to happen.

A broad rewrite may address structure, but it increases delivery risk. The record does not say a rewrite was the chosen or completed plan.
